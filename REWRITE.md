# Переезд на React

Задание для новой сессии. Здесь — намерение и границы, а не готовое решение: чем именно
пользоваться и как раскладывать код, решает тот, кто будет делать.

## Что это за проект

Личный инструмент для игры Outerplane: вбиваешь предмет (слот, грейд, сет, сабстаты) и получаешь
вердикт «оставить / временно / фоддер / спорно / разобрать» плюс список персонажей, которым он
подойдёт. Вторая вкладка — во что одевать конкретного персонажа. Данные — курированные билды
[outerpedia](https://github.com/Sevih/outerpedia).

- репозиторий: https://github.com/cotton-more/outerplane-gear-check
- сайт: https://cotton-more.github.io/outerplane-gear-check/

В архиве гита нет. Подключить обратно: `git init && git remote add origin
git@github.com:cotton-more/outerplane-gear-check.git`, или просто склонировать заново и перенести правки.

## Как устроено сейчас

`template.html` — 1465 строк, из них 27% CSS, 70% JS, разметки почти нет. `update.py` (1325 строк,
Python без внешних пакетов) качает данные outerpedia, подставляет их в шаблон и собирает **три формата**:

| Что | Куда | Зачем |
|---|---|---|
| PWA-сайт | `docs/` | GitHub Pages, установка на телефон |
| Одиночная страница | `outerplane-gear.html` | один файл, иконки в base64, работает офлайн (не в git) |
| Фрагмент без обёртки | `build/artifact.html` | для Claude Artifact (не в git) |

Публикация ручная и локальная: собрал, посмотрел, закоммитил, запушил — Pages раздаёт `docs/`
из ветки `main`. Подробности в `PUBLISH.md`. Никаких GitHub Actions в проекте нет намеренно.

Иконки приложения рисуются процедурно в `update.py` (`render_app_icon`) — буква O из логотипа
Outerplane с искрой. Тот же знак в шапке страницы — инлайновым SVG в `template.html`.

## Что хотим

Полноценное приложение на React. Главная цель — **модульность**: компоненты, хуки, чистая логика
отдельно от представления, чтобы можно было открыть нужный файл, а не листать простыню.

Важная оговорка: **компонент ради компонента не делаем**. Шапку можно вынести в компонент, если это
что-то реально даёт. Критерий — переиспользование, изоляция состояния или заметно более лёгкое
чтение. «Чтобы было по фэншую» — не критерий. Лучше пять осмысленных модулей, чем тридцать
однострочных.

Что переезжает легко:

- **Логика оценки уже чистая** и про DOM ничего не знает: `subWeights`, `scoreBuild`, `evaluate`,
  `evalArmor`, `evalGear`, `flatFactor`, `rollInfo`, `dedupe`, `rows`. Переносится почти как есть.
  Все пороги собраны в блоке `CFG` в начале скрипта — это сознательно, пусть так и останется.
- **Состояние** — один объект `state` плюс `roster` (Set) плюс `localStorage` (`persist`,
  `saveRoster`). Просится в хуки.
- **Рендер** — полтора десятка функций `render*`, которые собирают строку HTML и кладут её через
  `innerHTML`; `renderAll()` перерисовывает всё разом. Это ровно то место, которое React и заменяет.

## Сборка

Двухшаговость (`npm run build`, потом `update.py`) приемлема, но её стоит спрятать за Taskfile или
чем-то подобным. Заодно имеет смысл сложить туда же остальные команды, чтобы ничего не набирать
руками: сборка PWA, локальный просмотр, одиночный файл и вариант для артефакта, обновление данных
из outerpedia, публикация (собрать → закоммитить → запушить), проверка выкладки на Pages.

Чем именно — Taskfile, just, make, npm scripts — на усмотрение.

## Что нельзя потерять

- Все три формата вывода.
- Офлайн-режим. Версия service worker считается как хэш содержимого `docs/` — по нему телефон
  понимает, что вышло обновление, и показывает плашку «Вышли новые данные». Если данные не менялись,
  сборка должна получаться байт в байт той же, иначе будут ложные «обновления».
- PWA: manifest, иконки, установка на телефон, относительные пути (сайт живёт в подпапке).
- Ростер и настройки в `localStorage`, перенос кодом через «экспорт / импорт».
- Страница должна открываться без сети.
- `README.md` и `PUBLISH.md` придётся переписать под новую сборку.

## Баг, который надо починить заодно

**У Epic-предметов сабстатов три. Четыре бывает только у Legendary.**

Сейчас в `renderSubStep` (`template.html:1074`) выбор блокируется одинаково для обоих грейдов:

```js
const dis = blocked.has(k) || (!on && n >= 4);
```

то есть у Epic можно отметить четвёртый сабстат, которого не бывает. Логика оценки грейд уже
учитывает правильно — `expected = legend ? 4 : 3` для брони (`:662`) и `expected = epic ? 3 : 4`
для оружия и аксессуаров (`:785`), — так что расходится именно ввод.

Подсказка в шапке шага (`:1070`) говорит «до 4 · у Epic изначально 3» — её тоже поправить:
у Epic просто 3, без «изначально». Заодно стоит пройтись по коду и проверить, нет ли других мест,
где четвёрка зашита без оглядки на грейд.

## Ещё одна дыра в вводе

У легендарного оружия и аксессуаров предмет обязательно надо найти в списке — пути «не нашёл»
нет (`renderItemStep`, `template.html:1019`). Обычно это не мешает: каталог собран из игровых
данных, а не из билдов, и предметы вне билдов так и подписаны — «нет в билдах outerpedia».
Но новый предмет, которого ещё нет в данных outerpedia, ввести будет нечем.

Стоит добавить «нет в списке» с переходом на тот же путь, по которому идут Epic: выбор main stat
и оценка по качеству ролла как временной замены.
