# Публикация на GitHub Pages

Проект выложен в [cotton-more/outerplane-gear-check](https://github.com/cotton-more/outerplane-gear-check)
и открывается по адресу https://cotton-more.github.io/outerplane-gear-check/.

GitHub Pages просто раздаёт папку `docs/` из ветки `main`: что попало в `main` — то и увидишь на телефоне.
Собирает `docs/` робот в GitHub Actions ([AUTOUPDATE.md](AUTOUPDATE.md)):

- **правки кода** — просто `git push`: робот пересоберёт сайт на опубликованных данных и сам выложит, если проверки
  зелёные (иначе — issue с причиной);
- **новые данные outerpedia** — робот раз в сутки открывает PR с отчётом, ты вливаешь.

`task publish` с твоего компьютера — тот же результат без робота, сразу и вместе со свежими данными.

## Что нужно на компьютере

- **Node.js** с npm — `node --version`. Собирает приложение (Vite, React); зависимости ставит `task setup`.
- **Python 3.9+** — `python3 --version`. Качает данные outerpedia; внешние пакеты не нужны.
- **go-task** — `brew install go-task`. Все команды проекта: `task --list`.
- **git** — `git --version`.
- **GitHub CLI (`gh`)** — только для разовой настройки Pages командой; можно обойтись сайтом.

Автор коммитов записан в `.git/config` этой папки: `CMore <108236+cotton-more@users.noreply.github.com>`.
Если клонируешь заново — `git config user.name CMore && git config user.email 108236+cotton-more@users.noreply.github.com`.

## Разовая настройка

Делается один раз. Репозиторий уже создан и запушен, осталось включить Pages.

**Через сайт:** репозиторий → Settings → Pages → Source: **Deploy from a branch** → Branch: `main`,
папка `/docs` → Save.

**Или командой:**

```bash
gh api -X POST repos/cotton-more/outerplane-gear-check/pages --input - <<'JSON'
{"source": {"branch": "main", "path": "/docs"}}
JSON
```

Через минуту-две открой https://cotton-more.github.io/outerplane-gear-check/. На телефоне: Chrome →
меню ⋮ → «Установить приложение».

## Обычный цикл работы

**Правки кода:** закоммитить и `git push` — дальше робот. Минуты через 3–4 сайт обновится; следишь на вкладке Actions
(прогон «Обновление сайта»). Перед следующей работой — `git pull`: робот добавил в `main` коммит со сборкой.
Посмотреть до пуша — `task dev` или `task preview` (сайт как на Pages); оба `docs/` не трогают.

**Данные:** ничего — придёт PR, влить.

**Без робота, со своего компьютера — одной командой:**

```bash
task publish                         # сообщение коммита — «Обновление данных outerpedia»
task publish MSG="Правка порогов"    # своё сообщение
```

Она подтянет `main` с GitHub (там могут быть влитые PR с данными и коммиты робота со сборкой), прогонит тесты, соберёт `docs/` со свежими
данными, проверит сборку против опубликованной (`task check` — те же проверки, что у робота), закоммитит всё
(`git add -A`), если есть что коммитить, запушит и дождётся, пока Pages начнёт отдавать новую версию.
Красные проверки останавливают публикацию до коммита — причина в выводе.

**Или по шагам**, если хочется сначала посмотреть:

1. **Собрать** — `task build:pwa`. Соберёт приложение, сходит за свежими данными outerpedia, пересоберёт `docs/`
   и напечатает, что изменилось.
2. **Посмотреть локально** — `task preview` и открыть http://localhost:8000. Это ровно то, что окажется на Pages,
   включая офлайн-режим (service worker работает на `localhost` как на настоящем сайте): копия `docs/` из шага 1,
   пересобранная в `build/preview` с текущим кодом. Остановить — `Ctrl+C`.
   Для проверки на телефоне удобно сузить окно браузера до половины экрана.
3. **Проверить** — `task check`: ничего не пропало, страница рисует всё, сколько вердиктов изменилось.
   **Закоммитить и запушить** — `git add -A && git commit -m "…" && git push`.
4. **Дождаться выкладки** — `task pages:check`. Сравнивает версию в выложенном `sw.js` с локальным `docs/sw.js`
   и ждёт, пока они совпадут (обычно 1–2 минуты).

При следующем открытии PWA на телефоне появится плашка «Вышли новые данные — Обновить»: версия service worker
считается как хэш содержимого `docs/`, поэтому телефон замечает изменения сам, а если ничего не менялось — не дёргает зря.
На вкладке Actions при выкладке мелькает запуск `pages-build-deployment` — это внутренний механизм GitHub для режима
«из ветки», не наш workflow, настраивать там нечего.

## Если что-то пошло не так

- **`update.py`: «Нет build/app/index.html»** — приложение не собрано. Запускай через `task build:pwa` /
  `task build:single`: они собирают его сами (или `task build:app` отдельно).
- **«Не удалось узнать коммит outerpedia»** — исчерпан лимит GitHub API (60 запросов в час). Подожди и повтори.
  Собирать без sha нельзя: телефон получил бы ложное «обновление».
- **Сайт отдаёт 404** — проверь в Settings → Pages, что источник именно `main` / `/docs`, и что файл
  `docs/.nojekyll` на месте (без него GitHub прячет папки, начинающиеся с подчёркивания).
- **Телефон показывает старое** — открой сайт в обычном Chrome (не в установленном приложении) и обнови
  страницу; если и там старое, значит пуш ещё не доехал (`task pages:check`). Крайняя мера: удалить приложение
  и поставить заново, ростер перед этим сохранить через «экспорт».
- **`git push` отклонён** — на GitHub есть коммиты, которых нет локально (например, коммит робота со сборкой или влитый PR с данными):
  `git pull --rebase`, затем снова push. `task publish` делает это сам.
- **`task check`: «Код закоммичен»** — страница собрана с незакоммиченными правками в `src/` и т. п.; версия в подвале
  была бы неверной. Закоммить правки кода отдельно, потом снова `task publish`.
- **`task check`: другая красная проверка** — то же, что красный отчёт робота: причина в первой строке,
  разбор — в [AUTOUPDATE.md](AUTOUPDATE.md).
- **Другое имя репозитория** — замени `outerplane-gear-check` в командах и в `PAGES_URL` в `Taskfile.yml`;
  адрес станет `https://cotton-more.github.io/<имя>/`. Пути в сайте относительные, менять больше ничего не нужно.

Приватный вариант: бесплатный GitHub Pages работает только с публичными репозиториями.
Для приватного нужен GitHub Pro или другой хостинг (например, Cloudflare Pages с папкой `docs/`).

## Робот сайта

в Settings → Actions), что приходит и что с этим делать.
