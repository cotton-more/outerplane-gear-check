# Публикация на GitHub Pages

Проект выложен в [cotton-more/outerplane-gear-check](https://github.com/cotton-more/outerplane-gear-check)
и открывается по адресу https://cotton-more.github.io/outerplane-gear-check/.

Никакой автоматики на стороне GitHub нет: сайт собирается на твоём компьютере, а GitHub Pages просто раздаёт
папку `docs/` из ветки `main`. Что закоммитил и запушил — то и увидишь на телефоне.

## Что нужно на компьютере

- **Python 3.9+** — `python3 --version`. Внешние пакеты не нужны.
- **git** — `git --version`.
- **GitHub CLI (`gh`)** — нужен только для разовой настройки Pages. macOS: `brew install gh`.

Автор коммитов уже записан в `.git/config` этой папки: `CMore <108236+cotton-more@users.noreply.github.com>`.

## Разовая настройка

Делается один раз. Репозиторий уже создан и запушен, осталось включить Pages.

**Через сайт:** репозиторий → Settings → Pages → Source: **Deploy from a branch** → Branch: `main`,
папка `/docs` → Save.

**Или командой:**

```bash
gh api -X POST repos/cotton-more/outerplane-gear-check/pages --input - <<'JSON'
{"source": {"branch": "main", "path": "/docs"}}
JSON
```

Через минуту-две открой https://cotton-more.github.io/outerplane-gear-check/. На телефоне: Chrome →
меню ⋮ → «Установить приложение».

## Обычный цикл работы

Так выглядит любое изменение — и правка логики в `template.html`, и просто обновление данных из outerpedia.

**1. Собрать.**

```bash
python3 update.py --pwa docs
```

Скрипт сходит за свежими данными outerpedia, пересоберёт `docs/` и напечатает, что изменилось.

**2. Посмотреть локально.**

```bash
python3 -m http.server -d docs 8000
```

Открыть http://localhost:8000 — это ровно то, что окажется на Pages, включая офлайн-режим
(service worker работает на `localhost` как на настоящем сайте). Остановить — `Ctrl+C`.

**3. Закоммитить и запушить.**

```bash
git add -A
git commit -m "Обновление данных outerpedia"
git push
```

**4. Готово.** Через 1–2 минуты сайт обновится. При следующем открытии PWA на телефоне появится плашка
«Вышли новые данные — Обновить»: версия service worker считается как хэш содержимого `docs/`, поэтому
телефон замечает изменения сам, а если ничего не менялось — не дёргает зря.

Следить за выкладкой, если нужно: `gh api repos/cotton-more/outerplane-gear-check/pages/builds/latest --jq .status`
(ждём `built`). На вкладке Actions при этом будет мелькать запуск `pages-build-deployment` — это внутренний
механизм GitHub для режима «из ветки», не наш workflow, настраивать там нечего.

## Если что-то пошло не так

- **Сайт отдаёт 404** — проверь в Settings → Pages, что источник именно `main` / `/docs`, и что файл
  `docs/.nojekyll` на месте (без него GitHub прячет папки, начинающиеся с подчёркивания).
- **Телефон показывает старое** — открой сайт в обычном Chrome (не в установленном приложении) и обнови
  страницу; если и там старое, значит пуш ещё не доехал. Крайняя мера: удалить приложение и поставить заново,
  ростер перед этим сохранить через «экспорт».
- **`git push` отклонён** — на GitHub есть коммиты, которых нет локально: `git pull --rebase`, затем снова push.
- **Другое имя репозитория** — замени `outerplane-gear-check` во всех командах; адрес станет
  `https://cotton-more.github.io/<имя>/`. Пути в сайте относительные, менять больше ничего не нужно.

Приватный вариант: бесплатный GitHub Pages работает только с публичными репозиториями.
Для приватного нужен GitHub Pro или другой хостинг (например, Cloudflare Pages с папкой `docs/`).

## Если захочется автообновления

Сейчас данные обновляются только когда ты сам запустишь `update.py`. Два способа это автоматизировать:

- **Локально, через cron** — компьютер собирает и пушит сам (см. пример в `README.md`, раздел
  «Обновление данных»). Работает, только когда компьютер включён.
- **На стороне GitHub, через Actions** — вернуть workflow, который делал то же самое по расписанию.
  Он лежит в истории git: `git show d154c02:.github/workflows/pages.yml`. Тогда источник Pages нужно
  переключить обратно на **GitHub Actions** (`gh api -X POST .../pages -f build_type=workflow`).
