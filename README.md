# Outerplane Gear Check

Личная страница для быстрой чистки инвентаря в Outerplane. Открываешь её рядом с игрой — чаще всего на телефоне
в режиме разделённого экрана, — в несколько нажатий вбиваешь предмет и получаешь вердикт —
**Оставить / Временно / Фоддер / Спорно / Разобрать** — и список персонажей, которым он подходит.
Вторая вкладка — во что одевать конкретного персонажа.

Данные — курированные билды [outerpedia](https://github.com/Sevih/outerpedia) (`data/curated/gear-reco.json`)
и игровые таблицы снаряжения оттуда же. Сверено с живым сайтом: все 265 билдов 95 персонажей совпадают.

## Файлы

| Файл | Что это |
|---|---|
| `docs/` | PWA-сайт для GitHub Pages: `index.html`, иконки `img/`, `manifest.webmanifest`, `sw.js` (офлайн и обновления) |
| `src/` | приложение на React + TypeScript (устройство — в разделе «Разработка») |
| `index.html` | оболочка приложения для Vite: шрифты, маркер данных `/*__OGC_DATA__*/null`, точки разреза `<!--ogc:…-->` |
| `update.py` | качает данные outerpedia и подставляет их в собранное приложение (Python 3.9+, без внешних пакетов) |
| `pwa/sw.template.js` | шаблон service worker; `update.py` подставляет версию и список файлов |
| `test/` | эталон логики оценки (`golden.json`) и юнит-тесты |
| `Taskfile.yml` | все команды: `task --list` |
| `PUBLISH.md` | как выложить `docs/` на GitHub Pages и обновлять сайт |
| `AUTOUPDATE.md`, `AUTOINPUT.md` | планы на потом (не сделано): автообновление данных, автоввод предмета по скриншоту |
| `outerplane-gear.html` | одиночная страница — один файл, иконки встроены, работает офлайн (не в git) |
| `build/artifact.html` | та же страница без `<html>`-обёртки — для Claude Artifact (не в git) |

Кэш скачанных иконок лежит вне проекта — в `~/Library/Caches/outerplane-gear` (macOS) или `~/.cache/outerplane-gear`
(Linux). Его можно удалить в любой момент: следующий запуск скачает иконки заново за несколько секунд.

## Приложение на телефоне (PWA)

Открой сайт на GitHub Pages в Chrome и выбери в меню ⋮ «Установить приложение» (или нажми кнопку внизу страницы).
Появится иконка на рабочем столе: приложение открывается без адресной строки, работает офлайн и подходит для
разделённого экрана с игрой. Когда данные обновятся, при следующем открытии появится плашка
«Вышли новые данные — Обновить». Ростер хранится отдельно для каждого адреса: перенеси его через «экспорт / импорт».

## Как пользоваться

**Оценка предмета**

Форма рассчитана на разделённый экран рядом с игрой (проверено в 412×430 и 430×390): предмет из четырёх
сабстатов вместе с вердиктом помещается без прокрутки. Сет, предмет и main stat выбираются в окошках,
сабстаты — сеткой прямо на форме.

1. Слот (строка иконок) и грейд: `L` — Legendary (Etheric), `E` — Epic (Steel). Всё, что ниже 6★ Epic, — сразу в разбор
   (единственное исключение из билдов — Bloody Edge 5★ у Eliza, о нём напомнит слот оружия).
2. **Броня** — «Выбрать сет»: сет написан в названии после «of» (`Etheric Gloves of Speed` → Speed Set).
   **Legendary оружие/аксессуар** — найди предмет (фильтр класса и сортировка по спросу обычно избавляют от набора),
   потом сразу откроется выбор main stat. Предмета нет в списке (совсем новый, ещё не попал в данные outerpedia) —
   «нет в списке»: оценка пойдёт по main stat и роллу, как у Epic.
   **Epic оружие/аксессуар** (Steel Sword / Steel Necklace) — пассивки у них нет, поэтому сразу main stat.
3. Сабстаты — сетка 7×2: нажми статы по порядку, как на предмете в игре (у Epic их три, у Legendary четыре).
   %-статы стоят над своими flat-версиями (ATK% над ATK), чтобы «есть ли %» решалось местом кнопки.
   Ярче — статы, нужные хоть одному билду с выбранным сетом, блёклые не нужны никому. Если ярких на Epic-броне
   0–1, её можно разбирать, не вводя: «Оставить» и «Временно» требуют двух полезных статов под один билд
   (это проверяет тест `test/armor.test.ts`). У Speed, Immunity и Swiftness ярко почти всё — там подсветка не помогает.
   Выбранный стат встаёт строкой с 1 жёлтым сегментом; если выпало больше — нажми 2 или 3 прямо в строке (4 — редкость
   из спецмагазинов и Dimensional Supply). Нажатие на стат в строке — заменить другим (жёлтые сегменты остаются),
   ✕ — убрать. Пока отмечены не все сабстаты, вердикт просит отметить остальные, если от них ещё что-то зависит.
4. На телефоне готовый вердикт встаёт карточкой на место сетки: штамп, коротко почему и цепочка приоритета лучшего
   кандидата — что из нужного ему есть на предмете. Карточка появляется и раньше, если уже ясно, что в разбор.
   Нажми на неё — подробности (кому подходит, ролл, код) откроются шторкой. Внизу плашка: слева меню ☰,
   справа «Следующий» — очистить сабстаты для следующей вещи. На широком экране вердикт стоит колонкой справа.
5. **Код для гильдии.** В подробностях вердикта есть код предмета, например `OGC KXRM TPWA`: «Скопировать» —
   и вставь в чат игры (там 50 символов, а код — 8–11 букв). Кто получил, жмёт «Ввести код» (на телефоне — в меню ☰)
   и перепечатывает его: из игрового чата копировать нельзя, поэтому в коде только буквы (без цифр, I и O),
   а регистр, пробелы, дефисы и кириллические двойники букв не важны; контрольная буква ловит опечатку. Оценка у получателя — по его ростеру и настройкам.

**Язык** — русский или английский. Пока не выбран, берётся по языку браузера (русский для `ru`, иначе английский);
переключатель — в подвале (на телефоне — в меню ☰) и в «Справке», выбор запоминается (`ogc.lang`).

При первом запуске, пока ростер пуст, сверху карточка «Как пользоваться» (три шага и «Отметить персонажей»);
полная справка — «Справка» под формой или в меню ☰, там же «Как быстро разбирать». На iPhone и iPad кнопки «Установить» нет (Safari её не поддерживает),
поэтому там подвал и справка подсказывают: Safari → «Поделиться» → «На экран „Домой“».

На телефоне шапки нет, а редкое убрано с экрана в меню ☰ на нижней плашке: «Персонажи», «Ввести код», «Справка»,
«только мои персонажи», настройки оценки, язык и подвал с версиями. Во вкладке персонажей «← Оценка»
(или нажатие на вердикт текущей вещи) возвращает обратно.

В подвале две версии: данных (коммит outerpedia и дата снимка) и приложения — дата и хеш последнего коммита,
который менял код (`src`, `update.py`, `pwa`…). Коммиты с одними данными её не меняют, поэтому публикация без правок
кода не даёт ложной плашки «Обновить»; собрано с незакоммиченными правками — в строке есть пометка.

Недовведённый предмет сохраняется: если Android выгрузил приложение, пока ты в игре, после перезапуска продолжишь
с того же места. «Следующий» очищает предмет, но оставляет слот, грейд и сет брони: при сортировке инвентаря
по дате подряд обычно идут дропы одного забега. Убрал по ошибке — несколько секунд горит «Вернуть».
Сет брони переживает и смену грейда, и переход между шлемом, бронёй, перчатками и ботинками.

Если браузер открыл файл в режиме «Версия для ПК» (так бывает при открытии из «Файлов»), страница сама это распознает
и переключится на мобильную раскладку; надёжнее всё же выключить этот режим в меню Chrome ⋮. С клавиатуры:
`1`–`6` — слот, `L`/`E` — грейд, `Esc` — закрыть окошко или «Следующий».

**Персонажи** — поиск по имени. Одноимённые различаются префиксом: *Stella* / *Demiurge Stella*,
*Delta* / *Demiurge Delta* / *Heatwave Cop Delta*, *Snow* / *Core Fusion Snow*… Все билды outerpedia идут вкладками:
сеты (с альтернативами), оружие и аксессуар с main stat, приоритет сабстатов с подсказкой flat/%, талисманы, заметка.

**Ростер** — отметь звёздочкой своих персонажей, и оценка будет учитывать только их («только мои персонажи»).
Предмет, хороший для кого-то не из ростера, получит «Спорно», а не «Разобрать». Ростер хранится в браузере
(localStorage); «экспорт / импорт» переносит его кодом. Если персонаж на время пропадёт из данных outerpedia,
из ростера он не удалится. Ссылка `…/#demiurge-stella` сразу открывает персонажа.

## Как считается вердикт

**Броня.** «Полезный» сабстат — тот, что стоит на 1–3 месте в цепочке приоритета билда (4-е место — за ½, SPD — на
любом). Места считаются по статам: связка делит одно место, а следующий стат встаёт после всех её статов —
в `CHC › ATK › SPD=CHD › DMG UP%` у DMG UP% пятое место, как и в цепочке без связки. Берётся лучший билд среди персонажей, которые носят этот сет. В «Кому подходит» первыми идут те, у кого сет
основной (в первой связке билда), дальше — у кого он в запасных вариантах: шлем Attack Set прежде всего для атакеров
с Attack ×4, а не для Heatwave Cop Delta, у которой Attack только в связках 2 + 2.

- Оставить: 3+ полезных, или 2 полезных, если среди них SPD с 2+ жёлтыми сегментами.
- Epic строже: его не исправить камнями (по гайду outerpedia Transistone на Epic не тратят, в Breakthrough для Legendary
  он не годится), поэтому решают главные статы — первые два места цепочки, засчитанные целиком (flat-половинка не в счёт), —
  и ролл на них:
  - «Оставить» — три полезных, если среди них SPD или главный стат, либо 5+ жёлтых на полезных; или два главных стата
    с 5+ жёлтыми на них — тогда третий может быть любым;
  - «Временно» — главный стат с 2+ жёлтыми и ещё полезный, вместе 5+: носи, пока не выпадет вещь с недостающим главным
    статом (вердикт его называет); держать стоит 1–2 такие на сет и слот;
  - иначе — «Разбирай»; если все три полезны, но с нижних ступеней и с минимальным роллом, — «полезные, но слабые».
  Ловушка «всё про атаку»: DMG UP% даёт +2% за сегмент против +4% у ATK% и CHD, flat ATK (+40) слабее ATK% у персонажей
  с высокой базой, CHD без CHC работает вполсилы — такие вещи выглядят атакующими, но главных статов на них нет.
- Не дотянула Legendary — «Фоддер»: для Breakthrough и реролла Transistone (Total) сабстаты не важны, и гайд outerpedia
  советует такую красную броню не разбирать (держать стоит не больше 4 на сет и слот). Не копишь фоддер — выключи
  это в настройках, тогда и Legendary пойдёт в «Разобрать». Epic, не дотянувший до «Оставить», — всегда в разбор.
- Legendary с одним лишним сабстатом из четырёх: вердикт называет его — Transistone (Individual) меняет только
  этот сабстат, остальные три закрепляются. Transistone по гайду outerpedia тратят на Irregular и красную броню.
- Если отмечен flat ATK/DEF/HP, который не засчитался, а %-версия билдам нужна, вердикт просит проверить знак %:
  частая путаница — на предмете HP%, а отмечен HP.
- Сеты, которых нет ни в одном билде outerpedia (Critical Hit, Resilience, Fortification, Mitigation, Lifesteal,
  Bursting, Pulverization, Weakness), — «скорее разбирай» с объяснением. Список пересчитывается при обновлении данных.

**Flat ATK/DEF/HP.** %-сабстат умножает только собственную базу персонажа (уровень + эволюции + flat-бонусы Quirks),
flat прибавляет фиксированное число. Поэтому ценность flat считается для каждого персонажа отдельно, тем же расчётом,
что на outerpedia. В среднем flat ATK ≈ 0.9 от ATK%, flat DEF ≈ 1.0 от DEF%, flat HP ≈ 0.6 от HP%.
Слабый flat засчитывается за ½ или не считается. Уровень (100/120) и Quirks — в «Настройках оценки».

**Оружие и аксессуары.**

- Legendary с пассивкой из билдов и нужным main stat → оставить (сабстаты правятся Precise Craft / Transistone).
- С той же пассивкой, но не тем main stat → фоддер для Breakthrough (main stat не перебрасывается — так советует гайд outerpedia).
- **Временно**: предмет без нужной пассивки (любой Epic, Legendary не из билдов или «нет в списке»), у которого main stat — тот,
  что персонажи просят в этом слоте, **и хороший ролл**: у Epic (3 сабстата) — 3 полезных или 2 полезных с 5+ жёлтыми
  сегментами на них; у Legendary (4 сабстата) — 3 полезных. Иначе — «Разбирай — слабый ролл». Main ATK% на оружии
  просят 66 персонажей, SPD на аксессуаре — 58, но из случайных Epic проходит примерно каждый пятый-седьмой.
  Держи 1–2 лучших на каждый нужный main stat.
- Этап «Эндгейм» в настройках отключает временные замены: тогда в разбор идёт всё, что не рекомендовано. Исключение —
  Legendary «нет в списке»: пока его нет в данных outerpedia, неизвестно, рекомендуют ли его, поэтому он получает «Спорно».

**Ролл.** При отмеченных сабстатах вердикт показывает строку «Ролл: полезных N из M, жёлтых сегментов на них X из 3·M».
Если жёлтых на полезных статах 60%+ от максимума, появляется плашка «Стоит прокачать»: такой предмет выгодно
вкладывать в Reforge.

Процент в подсказке у персонажа — взвешенная оценка по местам в цепочке приоритета, используется для сортировки.
Все пороги — в блоке `CFG` в `src/config.ts`; после правки пересобери страницу (`task build:pwa` или `task build:single`)
и, если вердикты поменялись намеренно, обнови эталон (`task golden:update`).

## Обновление данных

Все команды — в `Taskfile.yml` (нужен [go-task](https://taskfile.dev): `brew install go-task`), список — `task --list`:

```bash
task build:pwa       # PWA-сайт в docs/ со свежими данными outerpedia
task build:single    # одиночная страница outerplane-gear.html (+ build/artifact.html)
task preview         # посмотреть docs/ на http://localhost:8000
task publish         # тесты → docs/ → коммит → пуш → дождаться выкладки на Pages
```

Сборка двухшаговая: `vite build` собирает приложение в `build/app/index.html`, потом `update.py` подставляет туда
данные и раскладывает три формата. Taskfile делает оба шага сам. Сайт обновляется вручную, с этого компьютера —
подробности и разовая настройка в [`PUBLISH.md`](PUBLISH.md). Если данные и код не менялись, сборка байт в байт та же:
лишних коммитов и ложных «обновлений» на телефоне не будет.

Скрипт берёт последний коммит outerpedia с GitHub, пересобирает страницу и печатает, что изменилось:
новые и пропавшие персонажи, обновлённые билды, переименования, новые предметы и сеты.
Новые персонажи помечаются на странице значком NEW. Ростер и настройки в браузере сохраняются.
Если outerpedia поменяет формат данных и какие-то рекомендации не сопоставятся, скрипт напишет об этом отдельно.
Если GitHub API недоступен (лимит 60 запросов в час), PWA не собирается: без sha коммита нельзя понять,
изменились ли данные, и телефон получил бы ложное обновление.

Флаги `update.py` передаются после `--`, например `task build:pwa -- --ref <sha>`:

- `--source ~/path/to/outerpedia` — взять данные из локального клона вместо скачивания;
- `--ref <sha>` — зафиксировать конкретный коммит;
- `--no-embed` — не встраивать иконки в одиночную страницу (файл ~0.5 МБ вместо ~2.3 МБ, но иконкам нужен интернет);
- `--refresh-images` — перекачать иконки, не глядя в кэш;
- `--out путь.html` — писать одиночную страницу в другое место (вариант для публикации ляжет рядом как `путь.artifact.html`);
- `--dump-json data.json` — дополнительно сохранить датасет в JSON.

Регулярное обновление можно повесить на cron, например раз в неделю по понедельникам
(в cron нет твоего PATH — укажи его явно):

```cron
0 10 * * 1 cd ~/Projects/outerplane-gear && PATH=/opt/homebrew/bin:/usr/bin:/bin task publish >> update.log 2>&1
```

## Разработка

```bash
task setup     # npm ci
task dev       # dev-сервер с горячей перезагрузкой; данные и картинки берёт из собранного docs/
task test      # проверка типов + тесты
```

Устройство `src/`:

| Где | Что |
|---|---|
| `config.ts` | `CFG` — все пороги и веса оценки |
| `data/` | типы датасета (зеркало `update.py`) и индексы поверх него |
| `logic/` | чистая логика без React и DOM: оценка брони (`evalArmor`) и оружия (`evalGear`), сабстаты под билд (`score`), списки панелей ввода, код предмета |
| `i18n/` | все фразы вердиктов и интерфейса: `ru.ts` и `en.ts` с одним набором ключей (`Texts`), выбор языка |
| `state/` | состояние страницы: reducer со всеми переходами, сохранение в localStorage, ростер |
| `hooks/` | раскладка (узкий экран, «Версия для ПК»), PWA, `#slug` в адресе, горячие клавиши |
| `components/` | компактная форма ввода и окна выбора (`eval/`), вердикт с плашкой и шторкой, персонажи (`chars/`), общие мелочи (шторка `Sheet`, картинки, плашки, шапка) |
| `styles/` | CSS, разложенный по тем же областям |

Логику оценки сторожит эталон `test/golden.json`: 800 детерминированных случаев и 80 списков панелей ввода.
Изначально он снят со старой страницы (до переезда на React) — `scripts/golden-old.mjs`. Намеренно поменял
поведение — `task golden:update` и просмотри diff эталона: в нём видно ровно те случаи, которые изменились.

Фразы — только в `src/i18n`: эталон сверяет русские тексты дословно, а `test/i18n.test.ts` проверяет английскую версию —

## Ограничения

- Рекомендации outerpedia в основном PvE; сеты без билдов (Resilience, Mitigation…) могут иметь нишевое PvP-применение.

- Классовые версии Briareos/Gorgon в игре называются одинаково: класс видно по иконке на плитке и суффиксу пассивки.
