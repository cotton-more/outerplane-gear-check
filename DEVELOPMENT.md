# Разработка

Как устроен проект, как собрать сайт и обновить данные. Для игроков — [README.md](README.md) (английский, витрина)
и [Wiki](https://github.com/cotton-more/outerplane-gear-check/wiki) (руководство на двух языках).

(Linux). Его можно удалить в любой момент: следующий запуск скачает иконки заново за несколько секунд.

## Команды

Все команды — в `Taskfile.yml` (нужен [go-task](https://taskfile.dev): `brew install go-task`), список — `task --list`:

```bash
task setup        # npm ci
task dev          # dev-сервер с горячей перезагрузкой; данные и картинки берёт из собранного docs/
task test         # проверка типов + тесты
task build:pwa    # PWA-сайт в docs/ со свежими данными outerpedia — шаг ручной публикации
task build:single # одиночная страница outerplane-gear.html (+ build/artifact.html)
task check        # проверить собранный docs/ против опубликованного (то же, что делает робот сайта)
task preview      # сайт как на Pages на http://localhost:8000: текущий код на данных из docs/ (в build/preview)
task screenshots  # переснять скриншоты для README и Wiki, оба языка (нужен Chrome)
task tour:check   # пройти тур обучения в Chrome на пяти размерах и в двух темах, кадры — build/tour-check/
task publish      # подтянуть main → тесты → docs/ → проверки → коммит → пуш → дождаться выкладки на Pages
```

Посмотреть правки до пуша:

- `task dev` — для работы над кодом: горячая перезагрузка, ничего не собирает;
- `task preview` — сайт ровно таким, каким его выложит робот после пуша: текущий код на тех же данных, что в `docs/`,
  с service worker и офлайн-режимом. Собирает копию в `build/preview` (`update.py --same-data`), `docs/` не трогает.

`task build:pwa` пишет в `docs/` — это шаг ручной публикации ([PUBLISH.md](PUBLISH.md)). Собранный так `docs/` не коммить
вместе с кодом: робот увидит «сайт уже собран из этого кода» и не прогонит свои проверки, а свежие данные outerpedia
уйдут на сайт мимо PR. К тому же после пуша робот закоммитит свою сборку `docs/`, и `git pull --rebase` откажется
при изменённом `docs/`. Передумал публиковать — `git restore docs`.

## Сборка и обновление данных

Сборка двухшаговая: `vite build` собирает приложение в `build/app/index.html`, потом `update.py` подставляет туда
данные и раскладывает три формата. Taskfile делает оба шага сам. Сайт обновляет робот в GitHub Actions (push с правками
кода — сразу, новые данные — через PR) или `task publish` с этого компьютера — подробности в [`PUBLISH.md`](PUBLISH.md) и [`AUTOUPDATE.md`](AUTOUPDATE.md).
PWA — функция только кода и снимка данных: дата данных — дата коммита outerpedia, а не время сборки. **Снимок**
(коммит outerpedia в «Ещё» → «О приложении» и версия данных в `sw.js`) двигается, только когда новые данные меняют то, что строит
текущий код: у outerpedia новый коммит — `update.py` ещё раз собирает опубликованный коммит тем же кодом и сравнивает
наборы; совпали (правили не наши файлы или то, чего мы не читаем) — снимок прежний. Поэтому, если данные и код не
менялись, сборка байт в байт та же: лишних коммитов нет, а правка одного кода даёт новую версию приложения без плашки
«Вышли новые данные». На Linux (Actions) сборка та же, что на Mac.

Скрипт берёт последний коммит outerpedia с GitHub, пересобирает страницу и печатает, что изменилось:
новые и пропавшие персонажи, обновлённые билды, переименования, новые предметы и сеты.
Новые персонажи помечаются на странице значком NEW. Ростер и настройки в браузере сохраняются.
Если outerpedia поменяет формат данных и какие-то рекомендации не сопоставятся, скрипт напишет об этом отдельно.
Если GitHub API недоступен (лимит 60 запросов в час) или не скачался опубликованный снимок для сверки, PWA
не собирается: иначе нельзя понять, изменились ли данные, и телефон получил бы ложную плашку «Вышли новые данные».

Флаги `update.py` передаются после `--`, например `task build:pwa -- --ref <sha>`:

- `--source ~/path/to/outerpedia` — взять данные из локального клона вместо скачивания;
- `--ref <sha>` — зафиксировать конкретный коммит;
- `--same-data` — с `--pwa DIR`: тот же коммит outerpedia, что уже в `DIR/index.html`, — пересобрать только код
  (так собирает `task preview`);
- `--no-embed` — не встраивать иконки в одиночную страницу (файл ~0.5 МБ вместо ~2.3 МБ, но иконкам нужен интернет);
- `--refresh-images` — перекачать иконки, не глядя в кэш;
- `--out путь.html` — писать одиночную страницу в другое место (вариант для публикации ляжет рядом как `путь.artifact.html`);
- `--dump-json data.json` — дополнительно сохранить датасет в JSON;
- `--report-json отчёт.json` — итог сборки для проверок: изменения, предупреждения, несопоставленные рекомендации,
  сдвинулся ли снимок данных (`dataChanged`, почему — `snapshot`) (`task build:pwa` пишет его в
  `build/data-report.json`, `task check` читает, робот по `dataChanged` решает, есть ли что предложить в PR).

Регулярное обновление данных и публикацию кода по push делает GitHub Actions — [AUTOUPDATE.md](AUTOUPDATE.md). Запрос sha коммита outerpedia
берёт `GITHUB_TOKEN` из окружения, если он есть (в Actions — лимит API выше).

**Версия приложения в «Ещё» → «О приложении»** — дата и хеш последнего коммита, который менял код (`src`, `index.html`,
`vite.config.ts`, `package.json`, `update.py`, `pwa`); её подставляет `vite.config.ts`. Не время сборки и не HEAD:
публикация коммитит данные, и иначе каждая пересборка меняла бы страницу — телефоны качали бы новую версию без
единой правки. Собрано с незакоммиченными правками в этих путях — в строке есть пометка.

**Обновление на телефоне** (`src/app/usePwa.ts`). В `sw.js` две версии: `VERSION` — хэш всех файлов сайта (новая
версия приложения от любой правки), `DATA` — коммит outerpedia снимка. Новый service worker ждёт; страница спрашивает
его (`ogc:info` через `MessageChannel`) и сравнивает `DATA` со своим `meta.commit`. Другие — плашка «Вышли новые
данные» с «Обновить». Те же, нет ответа (sw.js прежних выпусков) или у страницы нет коммита — обновилось только
приложение: наверху «Ещё» «Готова новая версия» с «Обновить», а если worker ждал уже при
загрузке страницы (холодный запуск), страница включает его сама и перезагружается — вещь на форме в `ogc.item`.
Строку `'skipWaiting'` в `sw.js` не менять: её шлют и страницы прежних выпусков.

## Устройство `src/`

Код разложен по фичам: папка — то, что видит игрок, а не слой техники. Зависимости — только вниз:
`shared` → `game` → `features` → `screens` → `app`. Фичи — в порядке `eval` → `gear` → `roster` → `worn` → `tryon` →
`trade`: каждая берёт (и логику, и вёрстку) только у тех, что левее. Где нижняя фича показывала бы верхнюю (форма
и вердикт — строки экипировки и режим героя), это экран — `screens/`. `i18n` и `tour` — сквозные. Правило сторожит
`test/layers.test.ts`. Импорт из другой папки — от корня, `@/features/gear/pool`; из своей — `./x`.

| `game/` | `data/` — типы датасета (зеркало `update.py`) и индексы поверх него; у Core Fusion поле `fusionOf` — id обычного героя (outerpedia `originalCharacter`); у сета `bonus` — бонусы 2P/4P на T0–T3 и T4 числом в единицах сабстата (`stat: null` — в статах не выразить), у персонажа `spd` — база SPD для бонуса Speed Set. `config.ts` — `CFG`, все пороги и веса оценки; `context.ts` — всё, от чего зависит оценка, кроме предмета. `item/` — вещь, как её вбили на форме, и у кого бывает Breakthrough (`item`: `ItemInput`, `hasBt`), сабстаты и их сегменты (`subs`), строки main и сабстаты, которых из-за них не бывает (`mains`). `set/setBonus` — бонусы сетов по Breakthrough. `build/` — запросы по билдам (`builds`), ключ билда героя и варианты связок (`variants`), сабстаты под билд и места в цепочке приоритета (`score`). `hero/` — имя героя по id. `icons/` — свои значки (`own.ts`: какой контур у стата, слота, сета, стихии, класса), контуры Tabler Icons, MIT (`tabler.ts`, генерирует `scripts/tabler-icons.mjs`), картинки и значки (`Img.tsx`) |
| `shared/` | без знаний об игре: шторка, плашка, жирный текст (`ui/`), раскладка — узкий экран, «Версия для ПК», липкая колонка, место сообщения с «Вернуть» на ПК (`layout/`), localStorage с префиксом `ogc.` (`storage`), значение, которое гаснет само (`useTimed`), вкладки (`tab`) |
| `i18n/` | все фразы вердиктов и интерфейса: `ru.ts` и `en.ts` с одним набором ключей (`Texts`), выбор языка |
| `tour/` | обучение: главный тур, подсказки модулей, якоря `data-tour`, что игрок уже прошёл (ниже — «Обучение») |
| `styles/` | CSS по тем же областям |

**Значки.** Статы, слоты, грейд, предметы, сеты, стихии, классы и талисманы рисуются своими значками — контурами
Tabler Icons (MIT), встроенными в страницу: у flat и %-версии одного параметра один контур, у %-версии в углу «%» (DEF
— щит, DEF% — щит с %). В режиме «свои» из игры остаются только портреты персонажей. Переключатель «Значки: из игры · свои» — в «Ещё» →
«Настройки»; без выбора — значки из игры (`ogc.gameIcons`), `update.py` по-прежнему качает картинки из игры. Новая иконка — дописать имя в `NAMES`
в `scripts/tabler-icons.mjs`, запустить `node scripts/tabler-icons.mjs` и выбрать её в `src/game/icons/own.ts`. Новый сет
без своего значка рисуется шестиугольником, отчёт обновления данных напомнит.

**Анимации** — все в `src/styles/motion.css`: только появление (шторки, карточка вердикта, полосы обучения и
подсказок, «Вернуть») и вспышка плашки вердикта при смене вердикта; 150–200 мс, только `transform` и `opacity`.
Закрывается всё сразу. Сетка, строки сабстатов, слот, грейд и текст вердикта не анимируются — ввод должен отзываться
мгновенно. «Уменьшить движение» в системе выключает все анимации (`base.css`); скриншоты снимаются без них.

Все пороги — в блоке `CFG` в `src/game/config.ts`; после правки пересобери страницу (`task build:pwa` или `task build:single`)
и, если вердикты поменялись намеренно, обнови эталон (`task golden:update`).

## Тесты

Логику оценки сторожит эталон `test/golden.json`: 800 детерминированных случаев и 80 списков панелей ввода.
Изначально он снят со старой страницы (до переезда на React) — `scripts/golden-old.mjs`. Намеренно поменял
поведение — `task golden:update` и просмотри diff эталона: в нём видно ровно те случаи, которые изменились.
Сам прогон `golden:update` печатает расхождения со старым файлом — это нормально, файл уже перезаписан.

Эталон и юнит-тесты работают на замороженном `test/fixtures/data.json` (outerpedia a31f580; поля `mainBlocks`,
`fixedMains`, `fixed` и `bonus` у сетов и предметов, `fusionOf` и `spd` у персонажей дописаны тем же `update.py` с того же коммита), поэтому свежие данные
outerpedia сторожит отдельная проверка — `scripts/check-data.mjs` (`task check`, робот сайта): собранная страница
в jsdom, те же
входы эталона на старых и новых данных, «каждый билд находит свою вещь». Что именно проверяется — в
[AUTOUPDATE.md](AUTOUPDATE.md).

Юнит-тесты — на правила, которые легко сломать незаметно: состояние и его сохранение (`appState`), броня (`armor`:
строгость Epic, места в цепочке со связками, «0–1 нужных стата — всегда в разбор» перебором всех сочетаний),
«нет в списке» (`unlisted`), код предмета (`itemCode`), строки main (`mains`: что запрещено в сетке и когда
main занимает место в цепочке).

Тесты лежат в `test/` по тем же папкам, что и код (`test/gear/`, `test/trade/`…); в корне — эталон, `i18n` и
фикстуры. В `src` их не перенести: в тестах русские фразы, а `test/i18n.test.ts` запрещает их в `src`. Раскладку
сторожит `test/layers.test.ts`: каждый файл — в своей папке, импорты только вниз по слоям и по порядку фич.

Фразы — только в `src/i18n`: эталон сверяет русские тексты дословно, а `test/i18n.test.ts` проверяет английскую версию —
все случаи эталона на английском без единой русской буквы, и в коде нет русских фраз мимо словаря. Новая фраза —
ключ в `ru.ts` и в `en.ts` (без второго TypeScript не соберёт).

## Обучение

`src/tour/`: туры (`tours.ts`) — главный «Первая вещь» (`core.ts`, пять шагов, пишется вручную) и «Экипировка»
(`gear.ts`, пять шагов на примере Caren · Speed); подсказки модулей (`*.tour.ts` рядом
с компонентом, их сам собирает `registry.ts` через `import.meta.glob`; порядок показа — «Что нового», подсказки по ходу, список в Справке — явный, `TIP_ORDER` там же), якоря (`anchors.ts`: элементы помечены
`data-tour`, одно имя на все раскладки — берётся первый видимый), хранение пройденного (`store.ts`, ключ `ogc.tour`),
слой на экране (`TourLayer.tsx`: рамка и полоса, на примере — приглушение с окном на каждую цель; где встать
полосе — `place.ts`). Тексты — раздел
`tour` в `ru.ts` и `en.ts`.

- На примере шаг засчитывается только при выборе из примера (`DEMO` в `core.ts`): рамки — на кнопках, которые
  осталось нажать (`pin`, кнопки помечены `data-tour-item`), остальное приглушено, но нажимается; что не так — строка
  `tour.off`. На своей вещи засчитывается любой выбор.
- Тур идёт с чистого листа: вещь на форме откладывается и в конце возвращается, сохранение страницы на время тура
  выключено (`useAppState` с `persist = false`) — если Android выгрузит страницу посреди тура, вещь не потеряется.
- Esc посреди тура закрывает его и не доходит до горячих клавиш (иначе нажал бы «Следующий» и стёр вещь); у шага может
  быть свой Esc (`esc`): на шаге «Следующий» Esc и есть «Следующий».
- Туров несколько — «Обучение» («Ещё», Справка) сначала спрашивает «Какое обучение?»; карточка новичка и
  «Появилось обучение» запускают главный. Пройденный тур — `seen['tour.<id>']`; главный ещё и `first: 'done'`.
- **Тур «Экипировка»** идёт на примере в памяти: у App своя экипировка и режим героя тура (`demo`), `ogc.gear`, `ogc.tryon`
  и ростер не трогаются, «Надеть» в туре не добавляет в ростер и не даёт «Вернуть». Шаг знает вкладку (`home`) и слой
  (`layer: 'card' | 'sheet'` — карточка персонажа во весь экран или шторка: полоса не сворачивается в плашку). Вещь
  примера тур кладёт на форму сам (`onStep`). В конце — прежние вкладка, персонаж, форма и режим героя.
- Подсказка с `tour` («Что нового» у экипировки): «Показать» запускает тур, а не подсказку.
- Само обучение предлагается только в окне высотой от 560px (`layout.tall`): в полоске разделённого экрана места
  мало. Кнопка «Обучение» в «Ещё» и Справке работает всегда.
- Давний игрок (отмечены персонажи или закрыта карточка «Как пользоваться») тур не получает — один раз полосу
  «Появилось обучение». По `ogc.state` его не узнать: страница пишет его с первого показа.
- **Новый компонент.** `test/tour/tour.test.ts` требует у каждого компонента `src/**/*.tsx` (кроме `src/tour`) свой `.tour.ts` или запись
  в `src/tour/coverage.ts` (`core` — объясняет главный тур, `helper` — служебный, `todo` — подсказка ещё не написана;
  причина — в комментарии, значения латиницей); новый `.tour.ts` — ещё строка в `TIP_ORDER` (`src/tour/registry.ts`), в
  своё место показа. Поменялось поведение, которое объясняет подсказка, — `rev + 1`: она
  покажется снова. Поменялся шаг тура — поправь его текст; `rev` шага пока только записывается, о новом давним игрокам
  скажет подсказка с `news`.
- **Подсказки по ходу** (`tips.ts`, `TipLayer.tsx`): одна за раз, не больше трёх за запуск, не чаще раза в 20 с и после
  паузы в нажатиях 1,5 с; только в окне от 560px, не во время тура и не поверх других полос. Увидена — когда закрыли
  или нажали на её якорь; сама ушла (якорь пропал или ушёл за край окна, условие `when` больше не верно) — покажется ещё.
- **Что нового**: подсказка с `news: true`, которой нет в `ogc.tour.known` или там она с меньшим `rev`. При первом
  запуске в `known` сразу ложится всё, что есть в приложении, поэтому новое — ровно то, что появилось после него; дата
  выпуска не нужна. Давний игрок (`first: skipped`, пришёл раньше обучения) о подсказках с `news` ещё не знает — они для
  него новые. Прогоны в Chrome (`tour-check`, `screenshots`) пишут `known` со всеми подсказками —
  `scripts/known-tips.mjs`. Полоса «Новое» сама; «Позже» — точка на ☰ («⋯» на ПК) и «Справке» в «Ещё» до просмотра;
  «Показать» — первая новая подсказка сразу. Открытая Справка тоже считается просмотром.
- **Сторожа.** `task test` в конце запускает `scripts/tour-audit.mjs`: коммиты после опубликованной сборки, которые
  меняют видимое игроку (компоненты, состояние, логику, `ru.ts`), но не трогают обучение и не несут строки
  «Обучение: …» в теле, — предупреждение (код выхода 0). `check-data` проверяет якоря главного тура на стартовом экране
  (ПК и 360px). `task tour:check` — оба тура в настоящем браузере; после правок вёрстки формы, вердикта и карточки
  персонажа.
- `test/tour/tour.dom.test.ts` проходит тур нажатиями на странице в jsdom (360px): заглушки `matchMedia` и
  `scrollIntoView`, после нажатия ждём кадр — слой меряет страницу раз в кадр.

## Хранилище и адреса

Состояние, ростер, язык, недовведённый предмет и пройденное обучение (`ogc.tour`) лежат в localStorage с префиксом `ogc.`; ключи и поднабор полей
совместимы между версиями, неизвестные id ростера не стираются. Ссылка `…/#demiurge-stella` открывает персонажа, `…/#OGH…` — карточку показа героя (код читается до того, как
`useHashRoute` перепишет адрес; в адресе он не остаётся, в хранилище ничего не пишется).
Если браузер открыл страницу в режиме «Версия для ПК», `useLayout` это распознаёт по `screen.width` и возвращает
мобильную раскладку.

Список персонажей: `ogc.state.cOwned` — режим «Мои» (true; «Доодеть» после перезапуска тоже «Мои»), false — «Все»; прежнее
`cAll` («показать и без билдов») не читается и не пишется. Пока ростер пуст, режим «Все» (`charMatches` режим не
подменяет — это делают список, `openCharAction` и `App`, который записывает «Все», пока ростер пуст), и первая
звёздочка его не меняет. Стихия и класс (`cel`, `ccl`) запоминаются, поиск — нет. `ogc.gameIcons` — значки; нет
записи — из игры.

`ogc.gear` v2 хранит ещё `worn` (надетое) и `aim` (выбранный билд героя). Инварианты: надетое ⊂ пул героя (`syncWorn` в
каждой мутации через `gc`); `aim` пишется только явно (Р17), показанный выбор — `aimOf`.
