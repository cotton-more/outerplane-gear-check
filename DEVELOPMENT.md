# Разработка

Как устроен проект, как собрать сайт и обновить данные. Для игроков — [README.md](README.md) (английский, витрина)
и [Wiki](https://github.com/cotton-more/outerplane-gear-check/wiki) (руководство на двух языках).

## Файлы

| Файл | Что это |
|---|---|
| `docs/` | PWA-сайт для GitHub Pages: `index.html`, иконки `img/`, `manifest.webmanifest`, `sw.js` (офлайн и обновления) |
| `src/` | приложение на React + TypeScript (устройство — ниже) |
| `index.html` | оболочка приложения для Vite: шрифты, маркер данных `/*__OGC_DATA__*/null`, точки разреза `<!--ogc:…-->` |
| `update.py` | качает данные outerpedia и подставляет их в собранное приложение (Python 3.9+, без внешних пакетов) |
| `pwa/sw.template.js` | шаблон service worker; `update.py` подставляет версию и список файлов |
| `test/` | эталон логики оценки (`golden.json`) и юнит-тесты |
| `scripts/` | проверка сборки перед публикацией (`check-data.mjs`), робот сайта (`autoupdate.sh`), снятие эталона со старой страницы (`golden-old.mjs`), скриншоты для README (`screenshots.mjs`) |
| `.github/workflows/data.yml` | робот сайта: push с правками кода — сборка и публикация на тех же данных; раз в сутки — PR с новыми данными ([AUTOUPDATE.md](AUTOUPDATE.md)) |
| `.nvmrc` | версия Node — одна в Actions и локально, чтобы сборки совпадали байт в байт |
| `screenshots/` | скриншоты на двух языках: `en/` — для README и английских страниц Wiki, `ru/` — для русских; пересоздаются `task screenshots` |
| `wiki/` | исходники страниц [Wiki](https://github.com/cotton-more/outerplane-gear-check/wiki): пары EN/RU, `_Sidebar.md`, `_Footer.md`. Правятся здесь, вместе с кодом; на push в `main` их публикует `.github/workflows/wiki.yml` — правка прямо в Wiki перезапишется |
| `Taskfile.yml` | все команды: `task --list` |
| `PUBLISH.md` | как выложить `docs/` на GitHub Pages и обновлять сайт |
| `AUTOUPDATE.md` | как работает автообновление данных и что делать с его PR и issue |
| `AUTOINPUT.md` | план на потом (не сделано): автоввод предмета по скриншоту |
| `outerplane-gear.html` | одиночная страница — один файл, иконки встроены, работает офлайн (не в git) |
| `build/artifact.html` | та же страница без `<html>`-обёртки — для Claude Artifact (не в git) |

Кэш скачанных иконок лежит вне проекта — в `~/Library/Caches/outerplane-gear` (macOS) или `~/.cache/outerplane-gear`
(Linux). Его можно удалить в любой момент: следующий запуск скачает иконки заново за несколько секунд.

## Команды

Все команды — в `Taskfile.yml` (нужен [go-task](https://taskfile.dev): `brew install go-task`), список — `task --list`:

```bash
task setup        # npm ci
task dev          # dev-сервер с горячей перезагрузкой; данные и картинки берёт из собранного docs/
task test         # проверка типов + тесты
task build:pwa    # PWA-сайт в docs/ со свежими данными outerpedia — шаг ручной публикации
task build:single # одиночная страница outerplane-gear.html (+ build/artifact.html)
task check        # проверить собранный docs/ против опубликованного (то же, что делает робот сайта)
task preview      # сайт как на Pages на http://localhost:8000: текущий код на данных из docs/ (в build/preview)
task screenshots  # переснять скриншоты для README и Wiki, оба языка (нужен Chrome)
task publish      # подтянуть main → тесты → docs/ → проверки → коммит → пуш → дождаться выкладки на Pages
```

Посмотреть правки до пуша:

- `task dev` — для работы над кодом: горячая перезагрузка, ничего не собирает;
- `task preview` — сайт ровно таким, каким его выложит робот после пуша: текущий код на тех же данных, что в `docs/`,
  с service worker и офлайн-режимом. Собирает копию в `build/preview` (`update.py --same-data`), `docs/` не трогает.

`task build:pwa` пишет в `docs/` — это шаг ручной публикации ([PUBLISH.md](PUBLISH.md)). Собранный так `docs/` не коммить
вместе с кодом: робот увидит «сайт уже собран из этого кода» и не прогонит свои проверки, а свежие данные outerpedia
уйдут на сайт мимо PR. К тому же после пуша робот закоммитит свою сборку `docs/`, и `git pull --rebase` откажется
при изменённом `docs/`. Передумал публиковать — `git restore docs`.

## Сборка и обновление данных

Сборка двухшаговая: `vite build` собирает приложение в `build/app/index.html`, потом `update.py` подставляет туда
данные и раскладывает три формата. Taskfile делает оба шага сам. Сайт обновляет робот в GitHub Actions (push с правками
кода — сразу, новые данные — через PR) или `task publish` с этого компьютера — подробности в [`PUBLISH.md`](PUBLISH.md) и [`AUTOUPDATE.md`](AUTOUPDATE.md).
PWA — функция только кода и коммита outerpedia: дата данных — дата коммита, а не время сборки. Если данные и код
не менялись, сборка байт в байт та же, в том числе когда у outerpedia новый коммит, не тронувший наши файлы: лишних
коммитов и ложных «обновлений» на телефоне не будет. На Linux (Actions) сборка та же, что на Mac.

Скрипт берёт последний коммит outerpedia с GitHub, пересобирает страницу и печатает, что изменилось:
новые и пропавшие персонажи, обновлённые билды, переименования, новые предметы и сеты.
Новые персонажи помечаются на странице значком NEW. Ростер и настройки в браузере сохраняются.
Если outerpedia поменяет формат данных и какие-то рекомендации не сопоставятся, скрипт напишет об этом отдельно.
Если GitHub API недоступен (лимит 60 запросов в час), PWA не собирается: без sha коммита нельзя понять,
изменились ли данные, и телефон получил бы ложное обновление.

Флаги `update.py` передаются после `--`, например `task build:pwa -- --ref <sha>`:

- `--source ~/path/to/outerpedia` — взять данные из локального клона вместо скачивания;
- `--ref <sha>` — зафиксировать конкретный коммит;
- `--same-data` — с `--pwa DIR`: тот же коммит outerpedia, что уже в `DIR/index.html`, — пересобрать только код
  (так собирает `task preview`);
- `--no-embed` — не встраивать иконки в одиночную страницу (файл ~0.5 МБ вместо ~2.3 МБ, но иконкам нужен интернет);
- `--refresh-images` — перекачать иконки, не глядя в кэш;
- `--out путь.html` — писать одиночную страницу в другое место (вариант для публикации ляжет рядом как `путь.artifact.html`);
- `--dump-json data.json` — дополнительно сохранить датасет в JSON;
- `--report-json отчёт.json` — итог сборки для проверок: изменения, предупреждения, несопоставленные рекомендации
  (`task build:pwa` пишет его в `build/data-report.json`, `task check` читает).

Регулярное обновление данных и публикацию кода по push делает GitHub Actions — [AUTOUPDATE.md](AUTOUPDATE.md). Запрос sha коммита outerpedia
берёт `GITHUB_TOKEN` из окружения, если он есть (в Actions — лимит API выше).

**Версия приложения в подвале** — дата и хеш последнего коммита, который менял код (`src`, `index.html`,
`vite.config.ts`, `package.json`, `update.py`, `pwa`); её подставляет `vite.config.ts`. Не время сборки и не HEAD:
публикация коммитит данные, и иначе каждая пересборка меняла бы страницу — у всех появлялась бы плашка «Обновить»
без единой правки. Собрано с незакоммиченными правками в этих путях — в строке есть пометка.

## Устройство `src/`

| Где | Что |
|---|---|
| `config.ts` | `CFG` — все пороги и веса оценки |
| `data/` | типы датасета (зеркало `update.py`) и индексы поверх него |
| `logic/` | чистая логика без React и DOM: оценка брони (`evalArmor`) и оружия (`evalGear`), сабстаты под билд и места в цепочке приоритета (`score`), списки панелей ввода и спрос сета на статы (`lists`), код предмета |
| `i18n/` | все фразы вердиктов и интерфейса: `ru.ts` и `en.ts` с одним набором ключей (`Texts`), выбор языка |
| `state/` | состояние страницы: reducer со всеми переходами, сохранение в localStorage, ростер |
| `hooks/` | раскладка (узкий экран, «Версия для ПК»), PWA, `#slug` в адресе, горячие клавиши |
| `components/` | форма ввода с сеткой сабстатов и окна выбора (`eval/`), вердикт с карточкой, плашкой, шторкой и цепочками, персонажи (`chars/`), общие мелочи (шторка `Sheet`, картинки, плашки, шапка) |
| `styles/` | CSS, разложенный по тем же областям |

Все пороги — в блоке `CFG` в `src/config.ts`; после правки пересобери страницу (`task build:pwa` или `task build:single`)
и, если вердикты поменялись намеренно, обнови эталон (`task golden:update`).

## Тесты

Логику оценки сторожит эталон `test/golden.json`: 800 детерминированных случаев и 80 списков панелей ввода.
Изначально он снят со старой страницы (до переезда на React) — `scripts/golden-old.mjs`. Намеренно поменял
поведение — `task golden:update` и просмотри diff эталона: в нём видно ровно те случаи, которые изменились.
Сам прогон `golden:update` печатает расхождения со старым файлом — это нормально, файл уже перезаписан.

Эталон и юнит-тесты работают на замороженном `test/fixtures/data.json`, поэтому свежие данные outerpedia сторожит
отдельная проверка — `scripts/check-data.mjs` (`task check`, робот сайта): собранная страница в jsdom, те же
входы эталона на старых и новых данных, «каждый билд находит свою вещь». Что именно проверяется — в
[AUTOUPDATE.md](AUTOUPDATE.md).

Юнит-тесты — на правила, которые легко сломать незаметно: состояние и его сохранение (`appState`), броня (`armor`:
строгость Epic, места в цепочке со связками, «0–1 нужных стата — всегда в разбор» перебором всех сочетаний),
«нет в списке» (`unlisted`), код предмета (`itemCode`).

Фразы — только в `src/i18n`: эталон сверяет русские тексты дословно, а `test/i18n.test.ts` проверяет английскую версию —
все случаи эталона на английском без единой русской буквы, и в коде нет русских фраз мимо словаря. Новая фраза —
ключ в `ru.ts` и в `en.ts` (без второго TypeScript не соберёт).

## Хранилище и адреса

Состояние, ростер, язык и недовведённый предмет лежат в localStorage с префиксом `ogc.`; ключи и поднабор полей
совместимы между версиями, неизвестные id ростера не стираются. Ссылка `…/#demiurge-stella` открывает персонажа.
Если браузер открыл страницу в режиме «Версия для ПК», `useLayout` это распознаёт по `screen.width` и возвращает
мобильную раскладку.
